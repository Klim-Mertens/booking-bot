# Бот записи клиентов «Barber Demo» — проект

Демо для портфолио: один движок записи, два мессенджера (Telegram и MAX).
Цель — показать заказчику готовый продукт, который за 1–2 дня перекрашивается под его бизнес.

## Что умеет (MVP)

1. Клиент: услуга → мастер → день → время → имя и телефон (после согласия на обработку ПДн) → подтверждение.
2. Напоминания за 24 ч и за 2 ч, отмена записи одной кнопкой.
3. Администратор: уведомление о новой записи, список записей на день, отмена, блокировка времени.
4. Telegram: выбор времени через HTML-виджет (Bot API 10.4) + запасной сценарий на обычных кнопках
   (для старых клиентов и как резерв). MAX: тот же сценарий на inline-кнопках.

## Архитектура

```
core/            — логика, не зависит от мессенджера
  models.py      — услуги, мастера, записи
  slots.py       — расчёт свободных слотов
  storage.py     — SQLite, защита от двойной записи
  crypto.py      — шифрование телефонов
  booking.py     — сценарии: записать, отменить, список
adapters/
  telegram/      — aiogram 3 + прямые вызовы sendWidget / answerWidgetQuery
  max/           — maxapi (сторонняя библиотека, MIT) или прямые HTTP-вызовы
widgets/         — HTML-виджеты (≤ 4096 байт после zlib)
config.example.toml — услуги, мастера, часы работы (то, что меняется под клиента)
```

Ядро ничего не знает о мессенджерах: адаптер переводит нажатия кнопок в вызовы `BookingService`.
Так добавить VK или WhatsApp — это новый адаптер, а не новый бот.

## Безопасность (отличие от конкурентов)

| Угроза | Мера |
| --- | --- |
| Утечка токена | токены только в переменных окружения, `.env` в `.gitignore`, проверка секретов в CI |
| Двойная запись на одно время | транзакция `BEGIN IMMEDIATE` + проверка пересечений в БД |
| Подделка `callback_data` / `data` виджета | данные — только ID; всё перепроверяется по БД; белые списки |
| Утечка ПДн из БД | телефон шифруется (Fernet, AES-128-CBC + HMAC), для поиска — HMAC-хэш |
| Лишние ПДн | собираем только имя и телефон, после явного согласия; автоудаление через N дней |
| Чужой доступ к админке | админы по числовому `user_id`, не по username |
| Флуд и перебор | ограничение частоты действий на пользователя |
| ПДн в логах | логи без телефонов и токенов |
| Поддельный webhook | `secret_token` в Telegram, только HTTPS (MAX требует это с 25.05.2026) |
